# 归一化优化设计与对话决策

版本：design-1，2026-10-19。状态：完整设计基线，待实现。稳定决策见 [DECISIONS.yaml](DECISIONS.yaml)。

## 1. 用户要求与设计出发点

本轮优化针对现有归一化的效率、成本与维护方式。用户明确指出：过去把归一化插入抽取过程，导致抽取链复杂、耗时和成本增加。因此新方案将统一身份放在独立后处理阶段；抽取阶段只为后处理留下便于利用的字段与来源。

用户确认以下方向：YAML 预先登记名称与身份；词典优先；未知名称登记；少量歧义判断；来源账本；局部更新；保留旧方案；先保存 GitHub 基线，再完整规划实现。不得把本轮已确定的架构拆成一个缺少关键保障的 MVP，也不得在后续阶段悄悄恢复全局两两判断或在线判同。

本文件的工程细则是为落实上述原则而作的本次规划决定，不等同于已经实现或逐项经过用户实测。后续若需改变，使用带证据的决策修订，不能仅为省事改变原意。

## 2. 现状证据与优化目标

旧 PFAS 离线流程：原始抽取入图 → 多路生成候选对 → 规则阻断 → LLM 逐对判断 → 保守聚类及簇审计 → 全图重写 → 最终数值实例及索引。

本轮从已完成断点只读统计：

| 项目 | 数量 | 解释 |
|---|---:|---|
| 原始图节点 | 15,300 | 已发生按节点名聚合，不是原始 mention 出现次数 |
| 候选对 | 88,969 | 多路召回的去重候选 |
| 规则阻断 | 46,019 | 约占候选 51.7% |
| 有效 LLM 判断 | 42,950 | 不是含失败及重试的 HTTP 请求数 |
| 含 formula_match 的候选 | 68,635 | 与其他召回理由可能重叠 |
| 共享 TiO2 的候选 | 50,956 | 共享组分不等于同一材料 |
| 共享 TiO2 且需要 LLM 的候选 | 15,913 | 表明身份入口过宽 |
| 最终规范实体 | 12,375 | 旧 hyper_norm 结果，不是新方案成绩 |

旧候选生成对同类型共享化学式作桶内两两组合；名称精确、别名表和化学式候选豁免 top-k。新方案应把可确定身份变成查表任务，并对剩余歧义设置明确上界。

目标同时包含：降低总处理成本、保持或改善身份准确性、保留证据与数值绑定、支持来源更新与撤回、保证旧方案可运行。现在没有新方案节省百分比的实测依据。

## 3. 从 Hyper-Extract 源码吸收的机制

本轮直接检查了本地 `hyper-extract` 源码，以及其依赖 `ontomem-0.6.1` 的展开源码。版本与文件哈希见 [baseline.json](baseline.json)。

| 源码机制 | 可借鉴的原则 | 在化工场景中的处理 |
|---|---|---|
| 模板工厂统一读取 output、identifiers、guideline、options | 声明式领域契约 | 同时生成抽取 schema、身份规则和索引投影规则 |
| identifiers 字段加载期校验 | 规则引用应在运行前失败 | 词典冲突、类型、作用域和单位定义一起预检 |
| OMem.add 先按 key 分组，新 key 直接插入 | 身份定位与内容融合分离 | 已知身份绑定；新身份登记；事实和来源由程序追加 |
| 融合前记录原始来源贡献 | 来源应可追溯 | 追加式账本作为真值层，支持撤回与重新绑定 |
| 受影响 key 局部更新索引 | 明确依赖与变更集合 | 由字段投影哈希驱动必要重嵌入与索引补丁 |

源码事实边界：模板超图关系键由 `relation_id` 声明，成员提取器不是关系身份规则；默认图融合可使用 LLM.BALANCED；经典 FieldMerger 用新非空字段覆盖旧字段；来源重算涉及 LLM 时不能保证逐字回滚。新设计吸收模块边界，不直接沿用这些化工身份和融合策略，也不默认新增 Hyper-Extract/OntoMem 运行依赖。

## 4. 固定原则

### 4.1 抽取与归一化分离（D01、D02）

抽取不查询全局身份候选、不调用判同模型、不把规范化完成作为单块抽取成功的前提。维持当前抽取调用阶段数；新增字段从同一次原文抽取中提供，缺失允许为空。新增输出 token 和验证开销仍须计入总成本。

抽取成功的最小记录：局部实体编号、原文名称、粗粒度对象类别、关系中的角色引用。按对象类别选填文中明确出现的缩写定义、型号、相态、组分、改性或样品标识。禁止为了填栏推断未知属性。

文档 ID、版本哈希、chunk ID、chunk 哈希、提取任务 ID、模型及提示版本、响应完成状态由程序附加。若模型给出短引文，程序校验并定位 span；多处相同引文不能随意选一个位置。局部编号与来源组合形成不可变 mention ID，不把全局 canonical ID 交给抽取模型创造。

### 4.2 身份定位与事实融合分离（D03、D07）

归一化只确定原始记录绑定哪个身份、关系类别或实例。确认身份后，别名、来源、证据作集合追加和幂等去重；测量值与工况保存为独立观测。常规融合不调用 LLM 摘要、不按新值覆盖旧值、不平均不同实验的数值。

### 4.3 不确定性是数据状态（D05、D09）

没有可靠候选时登记 provisional 身份，不强求模型确认“新建”。多义、范围不明或明确需要人工的记录保留 provisional/deferred_semantic 状态、原文和原因。它们可继续参与带状态的证据检索。

API 失败、截断、错误 JSON、伪引文和缺失必要字段属于技术未完成，不能改名为人工项，也不能假装 resolved。任务状态与可发布性分开记录。

## 5. 身份粒度和词典

### 5.1 四类对象

1. **概念身份**：材料家族、化学对象、指标、过程、条件维度等。
2. **变体／样品身份**：明确的组成、相态、改性、牌号、样品或制备批次；可以关联基础概念，不能自动视为同一对象。
3. **名称出现 mention**：某文档版本中某处名称及其局部含义。相同文字不保证同一身份。
4. **事实／观测 occurrence**：角色、实验条件、指标、值、单位、来源及陈述性质共同限定的记录。

BaTiO3 通用概念可共用；BaTiO3@TiO2 核壳材料保留独立身份并关联基础组分；锐钛矿与金红石若原文明确则保留区别。物种价态、电荷、同位素、立体信息及盐／酸／离子形式按实体种类的显式政策处理，不能靠去符号或统一小写消除。

实体的实验角色与对象种类分开：同一物质在文中作为污染物、载体或催化材料，不应只因角色变化就生成互不相干的物质身份。

未知属性不是“相同”证据。只有家族名称的 mention 可绑定家族概念；不能据此绑定某个特定样品。文档中的 Sample A 等标识默认限制在该文档或实验范围。

### 5.2 词典结构（D03、D04）

YAML 是稳定、可审查的身份与政策入口；运行时学习结果写入可追溯绑定库，按显式流程导出词典建议，不并发修改 YAML，不把模型建议直接升格为全局词条。

建议的配置结构如下；这是新协议设计，不是现有 Hyper-Extract 支持的语法：

```yaml
schema_version: registry-offline-v2.1
domain: pfas
entities:
  - canonical_id: material:batio3
    kind: material
    granularity: concept
    canonical_name: BaTiO3
    aliases:
      - text: BaTiO3
        normalizer: chemical_formula
      - text: BaTiO₃
        normalizer: chemical_formula
      - text: barium titanate
        normalizer: common_name
    scoped_aliases:
      - text: BTO
        scope: explicit_document_definition
    variant_dimensions: [composition, phase, modification, grade]
    merge_policy: append_evidence
```

每条 alias 有 kind、granularity、domain、scope、适用约束和来源政策。允许一个表面词对应多个带约束候选；禁止 first-wins。加载时拒绝无作用域却冲突的词条、重复 canonical ID 的矛盾定义、循环重定向、未知身份字段和不合法单位转换。

化学式正规化与普通名称正规化分离。普通名称可配置大小写折叠；化学式保留元素大小写和电荷等区别。模糊匹配键只用于找候选，不构成自动同一证明。

### 5.3 稳定 ID

YAML 中既有 canonical ID 显式固定；新运行身份使用命名空间内生成并持久化的不可变 ID，不从可变显示名称推导。临时身份的幂等创建键包含 kind、粒度、保护属性和必要的来源作用域。修改显示名称不改身份 ID。

合并、拆分和撤销形成新决策事件及重定向／绑定版本；不能删除原始身份与原判断。拆分按原始 mention 重新绑定，不能仅保留一个无法追溯的旧 ID 列表。

## 6. 离线解析顺序（D05、D06）

1. 验证原始抽取、来源版本和字段契约；只有完整成功的原始记录进入绑定。
2. 应用按种类配置的安全格式规则，建立保留身份区别的查找键。
3. 查询已审查 YAML、文档明确释义及满足同一作用域的已确认绑定；无冲突时直接绑定。
4. 在作用域和保护属性相容的范围内分组新任务；不能仅按同一字符串跨全文库去重。
5. 没有可信候选则幂等登记 provisional 身份；无须请求“确认新建”。
6. 有歧义时从词典索引和已知身份生成少量候选。候选来自完整名称、明确缩写、可靠标识和相容属性；共享化学式／组分只建立 related_to/has_component 线索。
7. 剩余任务可请求 LLM 从给定候选中选择 SAME_ID、NEW_ID、RELATED_VARIANT 或 UNCERTAIN。不能自由引用未提供的 ID；模型置信度不单独构成通过依据。
8. 校验原文支持、身份保护、候选范围与作用域；成功后追加绑定与证据事件。
9. 更新受影响事实和投影，并完成全量结构验收。

首次正式协议固定每任务最多 5 个候选。精确查找若产生超过上限的歧义，不随意截取前 5 个后强制判同；记录过宽原因并收紧作用域或保留未决。无候选上界豁免，不恢复桶内全组合。

首版候选不新增归一化专用 embedding；复用确定性索引。是否以后引入向量候选必须通过独立成本／准确性证据和决策修订，不作为隐式兜底。

### 6.1 判断任务的复用键

运行 manifest 固定完整词典和规则快照哈希；任务指纹包含安全名称键、kind、粒度、保护属性、作用域、身份证据签名、候选 ID 与版本、该任务实际依赖的词条／规则子集哈希、判断提示版本、模型 profile 内容与参数。完整快照用于复现，依赖子集用于精确失效；新增一个无关词条不能让所有成功判断失效。

同一文档里反复出现且含义不变的名称复用结果。跨文档复用需要相同适用政策与不冲突的身份依据。缓存命中不占用 API key。旧模型或旧政策下的判断不会无条件成为新任务的最终决策；可导入为具来源的建议。

### 6.2 请求预算与恢复（D10）

每次运行显式冻结 profile、规则和请求预算；没有 API 配置时允许纯离线登记，不暗中选择 QA 默认模型。默认遵守已授权的总实际并发上限 10、每物理 key 同时最多 1，所有角色／任务共享租用范围。

单任务有界重试，输出预算 4096/8192/16384；SDK 隐式重试关闭，由调度器统一管理实际发送、完成状态和脱敏证据。完整有效 JSON 与完整响应状态必须同时通过。成功任务不重发；预算耗尽标记 budget_deferred，不记为已完成审计。不得回退到旧全量判对流程。

当前 limiter 是进程／事件循环内状态，不能假称已提供跨进程总上限。新作业采用单一 API worker 服务或等价全局租约边界；CLI 与 Web，以及同时运行的抽取、查询、embedding 和归一化入口共享调度器，验收跨进程并发。不能只约束新角色却漏计同一凭据的其他入口；凭据身份也不能因 profile、端点别名或配置限额不同而分裂成多个独立槽。

## 7. 数值、事实和超边（D08）

指标身份、数值节点与实验出现分层。数值使用确定性十进制表示；单位保留原样并按显式量纲注册表转换。转换需量纲、指标及上下文相容；未知单位、绝对温度与温差不明、比例基准不明时保留原值并标记，不猜测换算。

值相同不意味着同一实验。每个 observation 记录实验／局部上下文、对象、指标、原值／规范值、单位、范围和来源。文中不明确实验范围时保留来源局部范围，不能自动跨段拼接工况。

事实身份使用关系类型、角色到身份的映射、条件／实验上下文、观测签名及必要的否定／假设／实测性质；成员顺序变化可不影响同一事实，但交换角色、改变指标、工况或陈述性质应保留区别。

现有 HypergraphDB 以节点集合聚合边，不能把它当作完整事实 ID。新方案保留独立 fact_store 和唯一 fact_id；原生图边可继续作为结构桶，保存对应 fact_ids。关系向量按 fact_id 建立，新检索适配器从 fact_store 恢复角色和来源。不得因同一成员集合而把矛盾事实融合为一条陈述。

## 8. 来源账本、事务与增量（D07、D11）

真值层保存文档版本、原始抽取、名称出现、别名断言、身份决策、绑定、事实与观测。JSONL 用于可审查导出；有约束的 SQLite 存储承担运行事务和索引。

文献更新顺序：提取新版本并校验 → 在暂存事务中计算新贡献与受影响对象 → 原子激活新版本并撤销旧版本贡献 → 生成派生变更任务。新版本失败时旧版本继续有效。来源撤回是可追溯事件，不删除原始证据。

图、BM25、向量和展示文本都是派生视图。记录 dirty IDs、投影内容哈希、索引版本和幂等 outbox；中断后补做未完成视图。不同视图尚未同步时不发布为一致完成。

只对内容、模型、维度或投影格式签名变化的对象重新嵌入；仅新增同义来源而索引文本不变时不重嵌入。向量写入先暂存校验，再原子切换 manifest；数据库事务不能替代文件与向量系统的发布协议。

## 9. 新旧方案兼容（D12、D13）

新策略名为 `registry_offline_v2`。旧在线实现与旧离线实现分别保留，并以 `legacy_online`、`legacy_posthoc` 作为新路由中的显式别名；原脚本及参数继续可用。

缺少策略字段的旧 run_config 按原入口和已有锁定配置解释，不能直接推断为 v2。原 `enable_entity_normalization` 不足以表达执行阶段，新作业额外记录 `normalization_strategy`、`normalization_phase` 和 `normalize_during_extraction`。

v2 固定独立后处理且 `normalize_during_extraction=false`。配置冲突在启动前报错，不能静默执行旧在线 hook。旧缓存的 ID、图、向量、run_config、检索结果和论文实验名称保持原版本；新结果使用独立目录，提供 profile/schema 路由。

旧缓存缺少原始字段时从完整、可定位的已缓存响应导入。无法证明的字段标记 unavailable；不能从聚合描述编造型号、数值、别名或原文位置，也不能为导入自动重抽取。

## 10. 完整完成的定义（D14—D18）

完整交付包括：契约编译、两领域词典、抽取钩子、离线解析、歧义判断、账本事务、事实／数值处理、图与索引投影、CLI/Web 集成、兼容导入、错误恢复、成本核验、科学质量核验及新旧方案对照。

分阶段构建用于验证依赖，不降低终态范围。离线模拟通过不能冒充真实 API 成本；同源缓存比较不能冒充新抽取字段开销；旧 LLM 标签不能冒充独立身份金标准。无真实独立质量证据时记录验收未完成，不宣称节省或准确性改善。

正式启用前用独立、预先冻结的身份审查集比较错合并／漏合并和未决率，并使用来源充分的盲审。需要人工的科学歧义按用户授权保留并继续其他工作，技术失败单列；科学质量门槛不足时保留双方案并列运行，不切换默认。

所有成本比较统计抽取新增 token、归一化输入输出 token、真实请求／重试、时长、embedding 请求和增量更新成本。价格按冻结的 profile 价目快照计算；没有价目或 usage 时标 unavailable，不能用请求数直接称货币成本。
